PAPER: A Lightweight Zero Trust Framework for Secure 5G VANET Vehicular Communication
AUTHORS: Muhammad Jamil, Muhammad Farhan, Farhan Ullah, Gautam Srivastava
SOURCE: IEEE Wireless Communications, December 2024

====================================================================
* ABSTRACT
====================================================================
VANETs enable V2V and V2I communication for Intelligent Transportation
Systems (ITS), but security is a major concern, especially with 5G
connectivity. Traditional trust-based security schemes and standard
authentication mechanisms are inadequate against modern cyber threats,
and fast-moving vehicles also suffer message delivery delays. The paper
proposes a lightweight zero-trust framework for securing V2V and V2I
communication in 5G VANETs using two algorithms. The framework enforces
continuous authentication and access control through a Centralized
Certification Server (CCS), and applies microsegmentation (visibility,
granular security, dynamic adaptation) to divide the network into secure
zones/clusters, limiting lateral movement after a breach. It combines
authorization, encryption, and anomaly detection. The framework is built
using lightweight RESTful web services, and performance was measured
using the Postman tool. Results show the framework prevents impersonation
attacks and strengthens legitimacy of vehicular communication with low
overhead.

====================================================================
* INTRODUCTION
====================================================================
- Motivation: Rapid urbanization has increased traffic congestion,
  pollution, and transportation overflow, driving the need for
  Intelligent Transportation Systems (ITS).
- ITS services include traffic monitoring, violation alerts, congestion
  analysis, road infrastructure analysis, pre-crash warnings, and message
  passing.
- VANETs support two communication types:
  * V2V (Vehicle-to-Vehicle): direct sharing of speed, location,
    direction between nearby vehicles.
  * V2I (Vehicle-to-Infrastructure): communication with traffic signals,
    tollbooths, smart highway systems, parking systems, etc.
- 4G VANETs suffer from bandwidth limitations and delay in message
  dissemination for fast-moving vehicles.
- 5G brings small cell networks, network slicing, edge computing, and
  beamforming — enabling ultra-high transmission rates and low
  end-to-end latency, making VANETs more ubiquitous and mission-critical.
- Problem: Traditional VANET security (trust-based schemes, cryptographic
  protocols, standard authentication) is inadequate against malicious
  actors as networks scale and become more dynamic.
- Solution direction: Zero Trust — no implicit trust; continuous
  verification and authorization before granting least-privileged access.
  Combined with microsegmentation and software-defined perimeters to
  contain breaches.
- Contribution: A zero-trust framework using a Centralized Certification
  Server (CCS) that authenticates vehicles via multi-factor verification,
  segments the VANET into secure clusters, and integrates encryption and
  anomaly detection — implemented as lightweight REST APIs (novel in this
  domain) tested over 5G.

====================================================================
* BACKGROUND
====================================================================
- VANETs are ad-hoc wireless networks formed by moving vehicles and
  roadside infrastructure to support ITS use cases (accident alerts,
  congestion reporting, emergency response, fuel/resource alerts).
- Location awareness is fundamental — VANETs rely on accurate vehicle
  location for time-critical services.
- 5G is positioned as the enabling wireless layer, replacing 4G to solve
  bandwidth and latency shortcomings via network slicing and edge
  computing.
- Zero Trust Architecture (ZTA) background: originally an enterprise
  network security paradigm where every user/entity is treated as
  untrusted by default; continuous verification and least-privilege
  access replace perimeter-based trust.
- Microsegmentation: splits a large heterogeneous network into isolated
  virtual subnets based on vehicle profile, geography, and communication
  pattern — reducing the attack/exposure surface and containing threats
  post-breach.

====================================================================
* OBJECTIVES
====================================================================
1. Design a lightweight zero-trust framework tailored to 5G VANETs for
   securing both V2V and V2I communication.
2. Use a Centralized Certification Server (CCS) to enforce continuous
   authentication and access control via multi-factor verification.
3. Apply microsegmentation to divide VANETs into secure clusters and
   restrict lateral movement/access between clusters.
4. Integrate encryption and anomaly detection to protect against
   impersonation, man-in-the-middle (MITM), and distributed denial of
   service (DDoS) attacks.
5. Implement the framework using lightweight RESTful web services (a
   novel approach for VANET communication) and empirically evaluate
   performance (response time, security resilience) using a third-party
   tool (Postman).

* LITERATURE REVIEW

The related work is organized around VANET service discovery,
communication issues, and security challenges:

- Service discovery architectures: centralized directory-based,
  directory-less, and distributed directory-based approaches [3];
  research also covered anonymous location-based/self-reliant routing

- V2V/V2I communication studies:
  * [4] Probability analysis of short-range V2V models (mmWave).
  * [5] Evolutionary algorithm-based vehicular clustering — minimizes

  * [6] Evaluation of VANET routing protocols in Madina city.
  * [7] Certificate-based authentication scheme — burdens vehicle
    storage due to certificate volume.
  * [8] P2P message-passing issues/challenges in V2V.
  * [9] Vehicle-Consensus Routing Management Scheme (VCRMS) — depends on
    inter-vehicle info exchange; reliability of shared info not
    guaranteed.
  * [10] Cloud architecture for vehicle-to-cloud communication; overview
    of VANET security challenges (data loss/breaches, DDoS, insider/
    outsider attacks, privacy, scalability, lightweight authentication).
  * [11] Comprehensive survey of VANET security issues: availability,
    confidentiality, authenticity, integrity, nonrepudiation; threats
    include DoS, jamming, malware, blackhole/greyhole attacks, spamming,
    eavesdropping, MITM, Sybil, tunnelling, GPS spoofing, impersonation,
    replay attacks, message tampering, repudiation.
  * [12] Markov renewal process model for message propagation speed
    between RSUs.
  * [13] Fog-technology-based distributed VANET architecture; evaluated
    via throughput, jitter, delay — limited to a single use case.
  * [14] SDN-enabled 5G VANETs for adaptive clustering and beamformed
    transmission — no analytical/simulation validation provided.
  * [15] Hash-based authentication protocol for IoV — lacks security
    analysis against diverse attacks.
- Key gap identified: existing VANET security approaches (encryption,
  certificates, PKI) face scalability issues in massive, fast-changing
  5G VANET environments; none combine zero-trust + microsegmentation +
  5G-native features (network slicing) the way this paper proposes.

====================================================================
* METHODOLOGY
====================================================================
The zero-trust framework enforces continuous authentication, granular
access control, and monitoring. Key components:

1. Centralized Server (CCS):
   - Handles identity verification, access control, and monitoring for
     all communication requests.
   - All vehicles must authenticate before sending messages.
   - Multi-factor authentication = One-Time Password (OTP) + digital
     signature.
   - Enforces least-privilege access — vehicles communicate only with
     authorized members of their own segment.

2. Microsegmentation:
   - VANET divided into secure zones/clusters.
   - Vehicles can only access/communicate within their own zone,
     preventing lateral movement of threats.
   - Zone access lists maintained centrally; segmentation adapted
     dynamically based on contextual data.

3. Anomaly Detection:
   - CCS continuously analyzes network traffic, vehicle credentials, and
     message timestamps for suspicious patterns.
   - Detected threats trigger immediate isolation or access revocation.

4. Encryption:
   - End-to-end encryption for all V2V and V2I communication.
   - CCS distributes/manages per-vehicle keys; session keys rotated
     periodically.

====================================================================
* METHODS
====================================================================
- Algorithm 1 (V2I Communication):
  Inputs: SenderID, MessageID, Message, Location.
  Steps: authenticate sender via onAuth() -> get next MessageID via
  getMaxID()+1 -> build Message (template + priority + timestamp) ->
  build Location (lat + long) -> if Location is null, prompt to turn on
  OBU location and retry; else mark "Message Sent Successfully" -> return
  JSON status.

- Algorithm 2 (V2V Communication):
  Inputs: SenderID, ReceiverID, ClusterID, MessageID, Message, Location.
  Similar to Algorithm 1, but additionally fetches ReceiverID via
  getClusterInfo() (returns all vehicle IDs in a cluster, receiver chosen
  from it), and includes ClusterID. Rest of the process (message
  composition, location check, response) mirrors V2I.

- Implementation stack: Lightweight web services written in native PHP
  (PHP 8), RESTful APIs, JSON key-value data exchange, MySQL database,
  Cloud-hosted server.

- Evaluation tool: Postman (third-party API testing tool) — used to
  measure response time, response size, socket initialization, DNS
  lookup, TCP handshake, transfer start, and download time, over 5
  different HTTP requests, tested under both cold and cached conditions.

====================================================================
* RESULTS
====================================================================
Security/Attack Resilience:
- Impersonation Attack: 0 successful impersonations out of 1000 attempts
  — a 100% improvement over standard cryptography-based authentication
  (compared to [11]).
- Distributed Denial of Service (DDoS): Compromised nodes isolated within
  2 minutes of detecting abnormal traffic, limiting impact to the
  affected cluster — 76% faster response vs. latency-to-traffic-density
  benchmark in [6].
- Man-in-the-Middle (MITM): End-to-end encryption prevented attackers
  from deciphering intercepted ciphertext; framework reduced adjusted
  breach likelihood score by 80% compared to [9]; automated policy
  enforcement lowered privilege revocation time by 90% after threat
  detection.

Performance (via Postman, HTTPS requests, 5 trials each for V2I and V2V):
- All 5 requests returned status code 200 (100% accurate web service
  hits); response size constant since the same message template was used.
- V2I timings (ms) ranged approx: Socket Init 1.40–2.18, DNS Lookup
  1.62–4.11, TCP Handshake 0.76–1.47, Transfer Start 80.91–98.18,
  Download 3.35–20.24.
- V2V timings (ms) ranged approx: Socket Init 1.04–11.24, DNS Lookup
  0.47–1.19, TCP Handshake 1.48–3.03, Transfer Start 58.95–93.56,
  Download 2.89–12.61.
- Variation across the 5 requests attributed to testing on moving
  vehicles (real-world network conditions).
- Response times improved substantially after Postman cache was enabled,
  showing efficient stateless client-side data handling.
- Overall: robust packet delivery ratio attributed to 5G's high
  bandwidth; lightweight nature and resource optimization cited as key
  performance drivers.

====================================================================
- Scale the research by building real-world applications for actual
  vehicle On-Board Units (OBUs), beyond simulated/lab testing.

====================================================================
* CONCLUSION
====================================================================
Traffic management in urban areas using 5G VANETs is the central theme
of the paper. It presents V2V and V2I communication secured via a
lightweight zero-trust framework built on a Centralized Certification
Server, microsegmentation, encryption, and anomaly detection. The
framework was implemented with lightweight RESTful web services and
evaluated for performance using Postman, showing strong throughput
(socket initialization, DNS lookup, TCP handshake) and packet delivery
rate, alongside strong resilience against impersonation, DDoS, and MITM
attacks. However, the proposed cloud-based design's effectiveness has
not been empirically verified against real-world deployment at scale;
the authors acknowledge limitations around scalability, infrastructure
resilience, and simulation constraints, and call for further real-world
validation and ML-based enhancements in future work.
